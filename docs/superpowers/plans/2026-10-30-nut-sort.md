**Goal:** Build Nut Sort, the tenth arcade game. It is a standalone repo `Nut-Sort-Game` (id `nutsort`) and is then integrated into the Arcade-Game-Center portal as v2.2.0.

**Architecture:**
- **Pure logic** in `src/logic/`: rules, solver, scoring, reducer and session guard.
- **Fixed levels** are generated offline into `src/logic/levels.json`, with a proven `par` and an optimal `solution` for each.
- **Rendering:** an SVG board with two looks (neon/glass).

**Tech Stack:** React 18.3, Vite 5.4, TypeScript 5.6, Vitest 2.1 + Testing Library + jsdom, ESLint 9. Scripts run with `vite-node`, which already ships with vitest, so there is no new dependency.

### Task 3: Exact solver, level generator and `levels.json`

**Date:** 2026-10-30 (solver) and 2026-10-31 (levels)

**Files:**

- Test: `src/logic/solver.test.ts`, `src/logic/levels.test.ts`

**Interfaces (produces):**

```ts
// solver.ts
export function canonicalKey(layout: Layout): string;           // bolt-order independent
export function heuristic(layout: Layout): number;              // admissible lower bound
export function solve(layout: Layout, opts?: { maxExpanded?: number }): Move[] | null; // optimal, or null if over budget
// levels.ts
export const LEVELS: readonly Level[];                          // levels.json, validated at import
```

**Heuristic:**
- Per bolt, find the maximal bottom run of a single type. Every nut above that run must move at least once.
- Per type, if bottom runs of that type sit on k > 1 bolts, every run except the largest must move entirely.
- The sum of both terms is admissible, because each nut is counted at most once.
- The solver is A\* on `canonicalKey`. If the solver needs it for speed, prune moves that take a nut from a bolt that is already complete (4 of one type) or from a single-type bolt onto an empty bolt. Both pruned moves are always useless.

**Generator (`scripts/generate-levels.ts`):**
- Use a seeded PRNG (mulberry32).
- For level *n*, take the band's `types` and `bolts`. Shuffle the 4×types nuts into `types` full bolts and add `bolts − types` empty bolts. Reject a layout that is already solved or contains a completed bolt.
- Call `solve` with a budget of `maxExpanded: 2_000_000`, and skip any seed that runs over it.
- Within a band, collect candidates and pick ones whose `par` is non-decreasing across the band's levels.
- Write `src/logic/levels.json` as `{ id, types, layout, par, solution }` for each level, along with the seeds used, so a re-run reproduces the file.

**Verifier (`scripts/verify-levels.ts`):** re-solves every level without a budget, asserts that `par` matches, and prints a per-level timing table.

### Task 4: Scoring, game reducer and session guard

**Date:** 2026-10-31

**Files:**
- Create: `src/logic/scoring.ts`, `src/logic/game.ts`, `src/logic/persist.ts`
- Test: `src/logic/scoring.test.ts`, `src/logic/game.test.ts`, `src/logic/persist.test.ts`

**Interfaces (produces):**

```ts
// scoring.ts
export const BASE_PER_TYPE = 100, RESTART_STEP = 0.2, RESTART_FLOOR = 0.2, UNDO_COST = 1;
export function restartCap(restarts: number): number;
export function levelScore(i: { types: number; par: number; moves: number; restarts: number }): number;
// game.ts
export type Phase = 'playing' | 'levelComplete' | 'finished';
export type GameState = {
  levelIndex: number;            // 0..19
  layout: Layout;
  history: Move[];               // net applied moves since level start/restart (undo pops)
  moves: number;                 // the scored counter (moves + UNDO_COST per undo)
  restarts: number;
  lifted: number | null;         // bolt whose top nut is lifted
  shake: { bolt: number; nonce: number } | null;
  levelScores: number[];         // one per completed level
  phase: Phase;
};
export type GameAction =
  | { type: 'select'; bolt: number } | { type: 'cancel' } | { type: 'undo' }
  | { type: 'restart' } | { type: 'next' } | { type: 'newRun' };
export function createInitialState(levelIndex?: number): GameState;
export function advanceGame(state: GameState, action: GameAction): GameState;
export function runScore(state: GameState): number;   // Σ levelScores
// persist.ts
export type SavedGame = GameState;
export function isNutSortSession(v: unknown): v is SavedGame;
```

**`select` semantics:**
- Nothing lifted and the bolt is non-empty: lift it.
- The bolt is the one already lifted: drop the nut back.
- `canMove(lifted, bolt)`: apply the move, `moves + 1`, push to history and clear the lift. If the layout is solved, push `levelScore` and set the phase to `levelComplete`, or `finished` after level 20.
- Otherwise: set `shake` with an incremented nonce and keep the lift.
- In any phase other than `playing`: a no-op.

**Other actions:**
- `undo`: pops the history and applies the reverse move, then `moves + UNDO_COST`. With empty history it is a no-op.
- `restart`: reloads the level layout, clears history and the lift, sets `moves = 0` and `restarts + 1`.
- `next`: works only in `levelComplete` and loads the next level with fresh counters.
- `newRun`: equals `createInitialState(0)`.
