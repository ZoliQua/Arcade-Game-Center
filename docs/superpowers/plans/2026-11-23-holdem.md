# Texas Hold'em Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build Texas Hold'em, the eleventh arcade game: a standalone repo `Texas-Holdem-Game` (id `holdem`), integrated into the portal as v2.3.0 after Nut Sort (v2.2.0).

**Architecture:**
- **Pure TypeScript engine** in `src/engine/`: cards, evaluator, betting and tournament.
- **Bots** in `src/bots/`: profiles, decisions and tells. Bots only ever see a `BotView`.
- **Controller** in `src/game/`: a reducer plus a timed bot scheduler.
- **Rendering:** an SVG table and React components in `src/ui/`.
- **Shell:** the vendored arcade kit, in the same patterns as Connect-Four-Game and Nut-Sort-Game.

**Tech Stack:** React 18.3, Vite 5.4, TypeScript 5.6, Vitest 2.1 + Testing Library + jsdom, ESLint 9, and `vite-node` for scripts. There are no new runtime dependencies.

**Spec:** `docs/superpowers/specs/2026-11-23-holdem-design.md`. Read it fully first; this plan does not repeat its rules and rationale.

## Review Focus

1. **The player double-clicks Raise/Call or presses Enter twice** while an action animation is playing. Only one action may be applied (Task 6 test).
2. **Multiple all-ins of different sizes,** including the player's, in one hand. Side pots must be correct, and the pot animation must split visibly (Tasks 3 and 7 tests).
3. **The tab is hidden or the game is paused while a bot is "thinking".** The bot must not act while paused, and on resume it acts exactly once (Task 6 test).
4. **Reloading mid-hand, at the exact moment the player must act.** The state is restored with the same cards, the same pot and the same log, with no new deal (Task 6 test).
5. **A phone in portrait at 360 px with 6 seats.** There is no horizontal scroll, the action bar is reachable, and the cards are readable (Task 8 browser check).
